title: Template Catalog

The template catalog is the repo data that powers starter selection in the CLI, `/new`, and official entries on `/browse`. Use it when you want to add or maintain a scaffoldable starter in this repository.

The directory is currently named `gallery/`, but it is not a standalone gallery service. It is a catalog of starter manifests and source files.

Templates are not the full set of things Render Harness can build. They are curated starting points that demonstrate common shapes. A good template should be valuable as-is for the matching use case, but it should also be easy to fork, edit, and extend into a different agent product.

Template catalog work is different from [registry publishing](/registry-publishing/). Catalog templates are starter source data used by the scaffolder. Registry publishing is for a finished deployable repo pinned to an immutable Git commit.

## Directory layout

```text
gallery/
  index.yaml
  agents/
    chat/
    support-bot/
    research-cron/
    chief-of-staff/
```

`gallery/index.yaml` lists each available starter. Each starter points at a directory with a `render-harness.yaml` manifest and optional preview/source files.

| `chat` | Minimal HTTP chat agent. | `web` |

## How it is loaded

The catalog can be loaded in two ways:

- From source during repo development.
- From the bundled snapshot shipped with `create-render-agent`.

The CLI wrapper chooses source or bundled mode:

- `--harness-root <path>` loads the live repo checkout.
- Default mode loads `bundled-gallery/gallery.json`.

## How to add a starter

Add a starter when you find a repeatable pattern that another author should not have to rediscover. That pattern might be a single agent, a multi-agent bundle, a runtime topology, or a capability combination.

To add a starter:

1. Create `gallery/agents/<slug>/render-harness.yaml`.
2. Add a `README.md` if the wizard should show preview text.
3. Add source files if the starter is a sealed bundle.
4. Add an entry to `gallery/index.yaml`.
5. Run registry and scaffolder tests.

The registry cross-checks the declared runtime kinds against the manifest.

### Bundle templates

A bundle template is the multi-agent version of a catalog starter. Use one when the starter's value comes from multiple agents working together in one Render Harness deployment.

Bundle templates add source files under `gallery/agents/<slug>/src/` and a manifest with multiple `agents[]` entries. They still follow the same catalog workflow: add files under `gallery/agents/`, register the starter in `gallery/index.yaml`, rebuild the bundled snapshot, and run registry and scaffolder tests.

For the detailed bundle shape, see [Authoring bundle templates](/authoring-bundle-templates/).

## Bundled gallery snapshot

`packages/create-render-agent/scripts/bundle-gallery.ts` serializes the source catalog into:

```text
packages/create-render-agent/bundled-gallery/gallery.json
```

That snapshot lets the published CLI work without cloning this repo.

## Naming note

The term “gallery” can be misleading because it is not the community registry. The current visual surfaces are `/browse` for discovery and `/new` for scaffolding.

If the project renames this concept later, `template catalog` or `agent templates` would better describe the current behavior.
