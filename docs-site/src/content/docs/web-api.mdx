title: Web API
description: Use the production HTTP surface for runs, conversations, streaming, agents, diagnostics, and usage.
---

`@render-harness/web` is the production HTTP surface. It fronts `runtime-worker`, stores state in Postgres, streams updates through SSE, and can mount the operator UI.

Use the web API when you want to integrate Render Loops with a custom frontend, webhook, Slack app, internal tool, or automation.

## Service shape

The web service:

- Applies database migrations on boot.
- Starts pg-boss.
- Creates the run queue.
- Authenticates requests.
- Registers run, conversation, agent, usage, diagnostics, deployment, Blueprint, config, Vitals, and model routes.
- Optionally mounts the operator UI. Scaffolded projects use the service root; library users can choose another path.

`serveWeb()` requires `DATABASE_URL`. The default auth checks `Authorization: Bearer <WEB_API_KEY>`.

## Run endpoints

| Endpoint | Purpose |
| --- | --- |
| `POST /runs` | Create a run and enqueue worker execution. |
| `GET /runs` | List runs with filters and keyset pagination. |
| `GET /runs/active` | Return the caller's most recent non-terminal run for an agent. |
| `GET /runs/:id` | Fetch a run and its message history. |
| `GET /runs/:id/tool-calls` | List tool calls and joined results for a run. |
| `GET /runs/:id/stream` | Stream run events over SSE. |
| `POST /runs/:id/cancel` | Request cooperative cancellation. |
| `POST /runs/:id/input` | Resume a paused run with human input. |

`POST /runs` accepts an `agentName` when a deployment serves multiple agents.

`GET /runs/active?agent=<name>` returns `{ "run": null }` when there is no active run.

## Conversation endpoints

| Endpoint | Purpose |
| --- | --- |
| `POST /conversations` | Create an ongoing thread. |
| `GET /conversations` | List conversations. |
| `GET /conversations/:id` | Fetch one conversation and message stream. |
| `POST /conversations/:id/messages` | Add a user turn and enqueue the next run. |
| `GET /conversations/:id/stream` | Stream updates across every run in a conversation. |

Conversations are the chat surface. A conversation can contain many runs over time.

Only one run in a conversation can be pending, running, or paused at a time. `POST /conversations/:id/messages` returns 409 `conversation_busy` if the previous turn is still active. Cancel the active run before sending the next message.

## Operator endpoints

| Endpoint | Purpose |
| --- | --- |
| `GET /agents` | Return loaded agents and skipped built-ins. |
| `GET /usage` | Return daily and per-agent usage rollups. |
| `GET /deployment` | Return bundle/deployment metadata for the UI. |
| `GET /diagnostics` | Return health checks for primitives and agents. |
| `GET /blueprint` | Return deployment Blueprint details. |
| `GET /vitals` | Return Render instances, CPU, memory, and HTTP latency for the current or selected service. Pass `?serviceId=` to target a sibling service in the same Render environment. Requires `RENDER_HARNESS_VITALS_ENABLED=1`. |
| `GET /vitals/services` | List sibling Render services in this loop (same Render environment), used to populate the Vitals tab's service picker. |
| `GET /vitals/logs` | Return recent Render logs with level, type, and text filters. Accepts `?serviceId=`. Requires `RENDER_OWNER_ID`. |
| `GET /healthz` | Liveness check. |

The config/model routes support in-product edits where the deployment has enough metadata and wizard integration configured.

## Streaming model

SSE streams are backed by Postgres notifications. The notification contains a pointer to durable state, not the full message. The client receives events and loads the corresponding rows from Postgres.

This keeps streams small and lets clients reconnect without losing durable history.

## Auth model

The default web auth is API-key bearer auth:

```http
Authorization: Bearer <WEB_API_KEY>
```

When the UI is enabled, the web package also accepts the signed UI session cookie created by `@render-harness/ui`.

You can pass a custom auth resolver to `serveWeb()` for JWTs, session cookies, or tenant-specific keys.
